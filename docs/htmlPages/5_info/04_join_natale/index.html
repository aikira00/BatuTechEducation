Le JOIN di Natale

Un database piccolissimo, natale, con dati che non vogliono dire niente: quattro colori, tre regali e tre persone. Serve a vedere come lavora ogni JOIN, riga per riga.

Niente chiavi esterne

Per questo Carla può volere un monopattino anche se in REGALO il monopattino non c'è. Con una FOREIGN KEY da PERSONA(regalo) verso REGALO(regalo) MySQL rifiuterebbe la riga di Carla.

Script per crearlo

CREATE DATABASE natale CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE natale;

CREATE TABLE COLORE (
  colore VARCHAR(20) PRIMARY KEY
);

CREATE TABLE REGALO (
  regalo VARCHAR(20) PRIMARY KEY
);

CREATE TABLE PERSONA (
  nome   VARCHAR(20) PRIMARY KEY,
  regalo VARCHAR(20)
);

INSERT INTO COLORE (colore) VALUES ('rosso'), ('verde'), ('bianco'), ('oro');
INSERT INTO REGALO (regalo) VALUES ('calzini'), ('sciarpa'), ('felpa');

INSERT INTO PERSONA (nome, regalo) VALUES
  ('Anna',  'calzini'),
  ('Bruno', 'calzini'),
  ('Carla', 'monopattino');

CROSS JOIN: tutte le coppie

COLORE e REGALO non hanno nessuna colonna in comune: non c'è modo di dire quale colore va con quale regalo. Si può solo accoppiare ogni regalo con ogni colore. È il prodotto cartesiano: 3 regali × 4 colori = 12 righe.

Query

SELECT *
FROM REGALO CROSS JOIN COLORE;

Lo stesso risultato si ottiene scrivendo le due tabelle separate da una virgola: FROM REGALO, COLORE. Le righe sono sempre le righe della prima tabella × le righe della seconda: con due tabelle da 1000 righe se ne ottiene un milione.

Quando c'è una colonna in comune

PERSONA e REGALO hanno una colonna in comune: regalo. Adesso si può dire quale riga di REGALO va con una persona: quella con lo stesso regalo.

Una JOIN si può pensare in due passi.

Primo passo: il prodotto cartesiano. Ogni persona con ogni regalo, come fa la CROSS JOIN: 3 persone × 3 regali = 9 righe.

Query

SELECT *
FROM PERSONA CROSS JOIN REGALO;

Risultato 9 righe

Secondo passo: la condizione di join.

PERSONA.regalo = REGALO.regalo

È vera solo nelle 2 righe evidenziate: Anna e Bruno con i calzini. La INNER JOIN tiene solo quelle; LEFT, RIGHT e FULL aggiungono anche le righe rimaste senza coppia.

Stesso nome, due tabelle

La colonna si chiama regalo in tutte e due le tabelle, quindi va scritta con il nome della tabella davanti: PERSONA.regalo e REGALO.regalo. Con ON regalo = regalo MySQL risponde con l'errore 1052: colonna ambigua.

INNER JOIN: solo le coppie

Tiene solo le righe che trovano una coppia nell'altra tabella.

Query

SELECT *
FROM PERSONA INNER JOIN REGALO
  ON PERSONA.regalo = REGALO.regalo;

Risultato 2 righe

nomePERSONAregaloPERSONAregaloREGALO
Annacalzinicalzini
Brunocalzinicalzini

calzini compare due volte perché lo vogliono in due. Carla, felpa e sciarpa non hanno una coppia e spariscono.

INNER si può omettere: JOIN da solo è una INNER JOIN. Lo stesso risultato si ottiene dal prodotto cartesiano con WHERE PERSONA.regalo = REGALO.regalo.

OUTER JOIN: anche le righe senza coppia

Le OUTER JOIN tengono anche le righe che non trovano una coppia. Dove manca la riga dell'altra tabella mettono NULL in tutte le sue colonne. Si scrivono LEFT, RIGHT o FULL; la parola OUTER si può omettere: LEFT OUTER JOIN e LEFT JOIN sono la stessa cosa.

LEFT JOIN: tutta la tabella di sinistra

La tabella di sinistra è quella scritta prima di LEFT JOIN, qui PERSONA. Restano tutte le persone; Carla non ha una coppia e riceve NULL nella colonna di REGALO.

Query

SELECT *
FROM PERSONA LEFT JOIN REGALO
  ON PERSONA.regalo = REGALO.regalo;

Risultato 3 righe

RIGHT JOIN: tutta la tabella di destra

Ora restano tutte le righe di REGALO, la tabella scritta dopo RIGHT JOIN. Felpa e sciarpa non le vuole nessuno: nelle colonne di PERSONA c'è NULL. Carla sparisce.

Query

SELECT *
FROM PERSONA RIGHT JOIN REGALO
  ON PERSONA.regalo = REGALO.regalo;

FULL JOIN: tutte e due le tabelle

Tiene tutte le righe delle due tabelle: le coppie, Carla con NULL a destra, felpa e sciarpa con NULL a sinistra. In MySQL FULL OUTER JOIN non esiste: si uniscono con UNION i risultati della LEFT JOIN e della RIGHT JOIN.

Query

SELECT *
FROM PERSONA LEFT JOIN REGALO
  ON PERSONA.regalo = REGALO.regalo
UNION
SELECT *
FROM PERSONA RIGHT JOIN REGALO
  ON PERSONA.regalo = REGALO.regalo;

Risultato 5 righe

nomePERSONAregaloPERSONAregaloREGALO
Annacalzinicalzini
Brunocalzinicalzini
CarlamonopattinoNULL
NULLNULLfelpa
NULLNULLsciarpa

UNION toglie le righe doppie: le righe di Anna e Bruno escono sia dalla LEFT sia dalla RIGHT, ma nel risultato compaiono una volta sola. Con UNION ALL le righe sarebbero 3 + 4 = 7.

Prova tu

Quante righe restituisce SELECT * FROM PERSONA CROSS JOIN COLORE;?

12: ogni persona con ogni colore, 3 × 4. La colonna in comune con REGALO qui non conta, perché la CROSS JOIN non ha condizione.

Scrivi una query che restituisca solo i regali che nessuno vuole.

Nella RIGHT JOIN i regali senza coppia hanno NULL nelle colonne di PERSONA: basta tenere quelle righe.

SELECT REGALO.regalo
FROM PERSONA RIGHT JOIN REGALO
  ON PERSONA.regalo = REGALO.regalo
WHERE PERSONA.nome IS NULL;

Escono felpa e sciarpa.

Se in PERSONA si aggiunge la riga ('Dario', 'felpa'), quante righe danno INNER, LEFT, RIGHT e FULL JOIN?

INNER 3 (Anna, Bruno, Dario). LEFT 4 (le 3 coppie e Carla). RIGHT 4 (le 3 coppie e sciarpa). FULL 5 (le 3 coppie, Carla e sciarpa).
