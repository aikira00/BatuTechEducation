Una String non cambia, un array sì

Dove finiscono le String scritte nel codice e quelle che arrivano da tastiera, perché == a volte funziona per caso, e cosa deve fare un costruttore copia quando dentro l'oggetto c'è un array.

1

Dove finiscono le String

Una String è un oggetto, quindi vive nell'heap. Ma dentro l'heap c'è un recinto riservato: lo string pool, dove la JVM tiene i letterali scritti nel codice. Stesso letterale, un oggetto solo. Tutto il resto, new, toUpperCase, tastiera, file, nasce fuori dal recinto. Eseguite il programma una riga alla volta.

Il trappolone. t1 == t2 dà true per merito del pool, non perché == confronti il testo. Con una String letta da tastiera lo stesso confronto dà false. Per il testo, sempre equals.

Costruttore copia: shallow e deep

Il salvadanaio di Anna dell'esercitazione 09, nella versione con lo storico. monete è il totale, settimana è un array con le monete versate giorno per giorno, da lunedì (0) a domenica (6). versa aggiorna tutti e due insieme: finché è così, la somma della settimana è uguale a monete.

Il main fa una prova: c è una copia di a, e il mercoledì si versa una moneta solo nella copia. a non dovrebbe accorgersene. Scegliete shallow o deep ed eseguite il main una riga alla volta: dopo la riga 4 guardate il totale e l'array di a. Potete cambiare versione in qualunque passo.

public Salvadanaio(Salvadanaio altro) {
    this.proprietario = altro.proprietario;
    this.monete = altro.monete;
    this.settimana = new int[7];
    for (int i = 0; i < 7; i++) {
        this.settimana[i] = altro.settimana[i];
    }
}

Salvadanaio.java · versa aggiorna due cose

public void versa(int giorno, int quante) {
    settimana[giorno] = settimana[giorno] + quante;
    monete = monete + quante;
}

Un int si copia, un array si condivide. this.monete = altro.monete copia il valore: i due totali sono indipendenti. this.settimana = altro.settimana copia la freccia: lo storico è uno solo, e la moneta che c versa finisce anche nell'array di a, che però non aggiorna il suo totale. proprietario è condiviso in tutte e due le versioni, ma è una String: nessuno la può cambiare, e la condivisione non fa danni.
3

Da portare a casa

  1. I letterali del codice stanno nello string pool, uno per testo. Tutte le altre String (new, metodi, tastiera, file) sono oggetti nuovi fuori dal pool.
  2. == confronta i riferimenti: sulle String a volte dice true, per caso. equals confronta i caratteri: funziona sempre.
  3. Un metodo di String non cambia la String: ne restituisce una nuova. Se la volete, assegnatela.
  4. Il costruttore copia crea un secondo oggetto che parte uguale al primo e poi vive per conto suo. Un int si copia col suo valore. Un array, o un oggetto che può cambiare, se si copia la freccia resta condiviso: va copiato anche lui (deep copy). Le String condivise non fanno danni.

Esercizi

Prevedi l'output, senza eseguire. Poi disegna stack e heap, con il pool.

String a = "fufi";
String b = new String("fufi");
String c = b;
System.out.println(a == b);
System.out.println(b == c);
System.out.println(a.equals(c));
a = a + "!";
System.out.println(a);
System.out.println(c);
Controlla

false, true, true, fufi!, fufi. Nel pool c'è un solo "fufi"; b e c arrivano allo stesso oggetto creato da new. a + "!" costruisce una String nuova e a la riceve: le altre due variabili non se ne accorgono.
