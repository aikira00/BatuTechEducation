Una String non cambia, una Data sì

Dove finiscono le String scritte nel codice e quelle che arrivano da tastiera, perché == a volte funziona per caso, e cosa deve fare un costruttore copia quando dentro l'oggetto c'è un altro oggetto.

1

Dove finiscono le String

Una String è un oggetto, quindi vive nell'heap. Ma dentro l'heap c'è un recinto riservato: lo string pool, dove la JVM tiene i letterali scritti nel codice. Stesso letterale, un oggetto solo. Tutto il resto, new, toUpperCase, tastiera, file, nasce fuori dal recinto. Eseguite il programma una riga alla volta.

Il trappolone. t1 == t2 dà true per merito del pool, non perché == confronti il testo. Con una String letta da tastiera lo stesso confronto dà false. Per il testo, sempre equals.

Costruttore copia: shallow e deep

Lo Studente dell'esercitazione 12 ha dentro una Data. Il costruttore copia copia le variabili d'istanza una per una: ma dataDiNascita è un riferimento. Copiare il riferimento (shallow copy) o copiare anche la Data (deep copy)? Scegliete una versione, poi eseguite il main. Potete cambiare versione in qualunque passo.

costruttore copia:

Perché la String si può condividere e la Data no. Nessuno può cambiare "Anna": i metodi di String ne restituiscono una nuova. Una Data invece ha setAnno: chi ha il riferimento la cambia per tutti. Per questo new Data(altro.dataDiNascita) serve, e new String(altro.nome) no.
3

Da portare a casa

  1. I letterali del codice stanno nello string pool, uno per testo. Tutte le altre String (new, metodi, tastiera, file) sono oggetti nuovi fuori dal pool.
  2. == confronta i riferimenti: sulle String a volte dice true, per caso. equals confronta i caratteri: funziona sempre.
  3. Un metodo di String non cambia la String: ne restituisce una nuova. Se la volete, assegnatela.
  4. Il costruttore copia copia le variabili d'istanza. Se una è un riferimento a un oggetto che può cambiare, copiate anche l'oggetto: deep copy. Le String condivise non fanno danni.

Esercizi

Prevedi l'output, senza eseguire. Poi disegna stack e heap, con il pool.

String a = "fufi";
String b = new String("fufi");
String c = b;
System.out.println(a == b);
System.out.println(b == c);
System.out.println(a.equals(c));
a = a + "!";
System.out.println(a);
System.out.println(c);
Controlla

false, true, true, fufi!, fufi. Nel pool c'è un solo "fufi"; b e c arrivano allo stesso oggetto creato da new. a + "!" costruisce una String nuova e a la riceve: le altre due variabili non se ne accorgono.
