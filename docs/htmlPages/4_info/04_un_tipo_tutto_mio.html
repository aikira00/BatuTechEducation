1

Tre array che non si parlano

Secondo guaio, stessa origine. Per stampare una pagella bisogna passare i pezzi uno per uno, e nell'ordine giusto:

void stampa_pagella(char nome[], char cognome[], char classe[],
                    float media, int assenze) {
    printf("%s %s %s media %.1f assenze %d\n",
           cognome, nome, classe, media, assenze);
}

stampa_pagella("Anna", "Rossi", "4B", 12, 6.5);
// media e assenze scambiate: il compilatore converte in silenzio
// (12 diventa 12.0, 6.5 diventa 6) e la pagella è falsa

Diagnosi. Il legame tra il nome, la media e le assenze di Rossi esiste solo nella testa di chi programma. Nel codice non è scritto da nessuna parte, quindi nessuno può difenderlo: nemmeno il compilatore.

2

Ci serve un tipo che si chiami Studente

Vorremmo che i dati di uno studente viaggiassero insieme, come una cosa sola. E vorremmo poter dire al linguaggio che cos'è quella cosa. In Java sapete già scrivere la prima riga. La seconda è quella che ci manca:

int x = 5;                      // tipo del linguaggio: int.   Valore: 5
Studente s = new Studente();    // tipo MIO: Studente.         Valore: un oggetto studente

Java conosce int, double, boolean, String. Non conosce Studente, né Canzone, né Partita. Non può: non sa cosa vi serve.

Una classe è il modo per aggiungere al linguaggio un tipo che gli manca: descrive com'è fatto. Un oggetto è un valore di quel tipo: esiste in memoria mentre il programma gira, come il 5 dentro x.

«Ma in C c'era la struct.» Vero, ed è metà della risposta: una struct Studente tiene insieme nome, media e assenze, e il problema della sezione 1 sparisce. Però le funzioni che lavorano su quei dati restano fuori, e chiunque può scrivere s.media = -5. Una classe mette nello stesso posto i dati e il codice che li usa. Questa è l'altra metà.

3

Prima del codice: cosa sa, cosa fa

Una classe si progetta su carta, con due domande sugli oggetti che ne nasceranno.

Cosa sa di sé ogni oggetto? Sono i suoi dati: le variabili d'istanza, cioè il suo stato. Cosa fa? Sono i metodi: il suo comportamento, che lavora su quei dati.

Una classe che avete già in tasca

Aprite la rubrica del telefono e premete +. Compare una scheda con dei campi vuoti: nome, numero. Non è nessuno. Dice solo come è fatto un contatto. Quella scheda vuota è la classe.

Compilate e salvate: adesso esiste un contatto, con i suoi valori. È un oggetto. Duecento contatti in rubrica, una sola forma del contatto.

Salvare un contatto è una new

chiama() è lo stesso per tutti i contatti, ma ogni volta compone un numero diverso: usa lo stato dell'oggetto su cui lo invocate. Stesso metodo, risultato diverso.

Dove la metafora si rompe. Nella rubrica siete voi a chiamare il contatto. In Java è l'oggetto stesso a eseguire il metodo, usando i propri dati. Tenetelo a mente: tra qualche lezione questo «se stesso» avrà un nome, this.

5

In Java: Studente e StudenteTestDrive

Due file. Il primo è il rettangolo della sezione 3 tradotto in Java. Il secondo serve solo a provarlo.

Studente.java

// La classe descrive COM'È FATTO uno studente.
// Qui dentro non c'è nessuno studente.
class Studente {

    // --- cosa SA: variabili d'istanza (stato) ---
    // Ogni oggetto avrà la SUA copia di queste variabili.
    int matricola;
    String nome;
    double media;
    int assenze;

    // --- cosa FA: metodi (comportamento) ---
    // Il codice è uno solo, ma lavora sui dati
    // dell'oggetto su cui viene chiamato.
    void presentati() {
        System.out.println(nome + ": media " + media
                                + ", assenze " + assenze);
    }

    void aggiungiAssenza() {
        // cambia lo stato di QUESTO studente, non degli altri
        assenze = assenze + 1;
    }
}

StudenteTestDrive.java

// Una seconda classe, che serve solo a provare la prima.
// main non è "il programma": è la porta da cui entra la JVM.
public class StudenteTestDrive {
    public static void main(String[] args) {

        Studente a = new Studente();   // primo oggetto
        a.nome = "Rossi";
        a.media = 6.5;

        Studente b = new Studente();   // secondo oggetto:
        b.nome = "Bianchi";            // stessi campi, valori suoi
        b.media = 8.0;

        a.aggiungiAssenza();           // tocca solo Rossi

        a.presentati();   // Rossi: media 6.5, assenze 1
        b.presentati();   // Bianchi: media 8.0, assenze 0
        // stesso metodo, output diverso:
        // cambia lo stato di chi lo esegue
    }
}

Il guaio della sezione 1 non può più succedere: non si possono ordinare le medie lasciando indietro i nomi, perché la media sta dentro lo studente.

Dove sta la classe, dove stanno gli oggetti

Compilate da terminale e guardate cosa compare nella cartella:

javac Studente.java StudenteTestDrive.java
Get-ChildItem *.class        # Studente.class e StudenteTestDrive.class
java StudenteTestDrive
javap -c StudenteTestDrive   # il bytecode: cercate l'istruzione new

Ogni classe diventa un file .class di bytecode. La JVM lo carica una volta. Gli oggetti nel file non ci sono: nascono mentre il programma gira, ogni volta che viene eseguita un'istruzione new, quanti ne servono. Una classe sul disco, tanti oggetti in memoria. Con NetBeans i .class finiscono in build/classes o target/classes dentro il progetto.

Cosa c'è davvero dentro s

Dentro int x c'è il numero. Dentro Studente s non c'è lo studente. L'oggetto vive in una zona di memoria chiamata heap. La variabile contiene soltanto il modo per raggiungerlo.

Due cose che si romperanno presto

La nostra classe funziona, ma si fida troppo. Provate queste righe in StudenteTestDrive:

a.media = -5;        // compila, gira, e il registro contiene una media impossibile

Studente c = new Studente();
c.presentati();      // null: media 0.0, assenze 0   (nessuno ha dato un nome a c)

Chi controlla che una media sia sensata? Chi garantisce che uno studente nasca con un nome? Per ora nessuno. Sono i problemi delle prossime due lezioni. Prima di allora, provate a romperla voi in altri modi.

8

Da portare a casa

  1. Una classe è un tipo che aggiungo al linguaggio. Un oggetto è un valore di quel tipo, vivo in memoria mentre il programma gira.
  2. Ogni oggetto sa qualcosa (variabili d'istanza) e fa qualcosa (metodi). Un metodo lavora sui dati dell'oggetto su cui lo chiamo.
  3. Una classe, quanti oggetti voglio. Stessi campi, ognuno con i suoi valori.
  4. La variabile non contiene l'oggetto: contiene il telecomando. t = s copia il telecomando, non lo studente.
  5. Studente.class sta sul disco. Gli oggetti nascono con new nello heap e muoiono quando nessuno li può più raggiungere.
